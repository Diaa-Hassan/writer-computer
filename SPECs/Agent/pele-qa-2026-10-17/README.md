# Pele QA, 2026-10-17

QA for [`SPECs/pele-diagrams-spec.md`](../../pele-diagrams-spec.md): Mermaid diagrams rendered by Pele 1.6.0 instead of beautiful-mermaid 1.1.3.

## Setup

- **Build under test:** release `Writer.app` (`tauri build --bundles app`, updater artifacts off) from `feature/pele-diagrams`: commit `a78608b` for flows A–E, then the XY chart fix (see Fixes), re-checked in the same VM.
- **Machine:** throwaway Tart VM, macOS 27.0.1, 1024×768 points at 2×, light/dark switched with System Events (`appearance preferences`; Writer's theme setting is System). Window 1024×680.
- **Driving:** `cliclick` for pointer moves, clicks and drags; AppleScript `keystroke` / `key code` for typing; a small Swift helper posting pixel scroll-wheel events (with ⌘ for zoom).
- **Recording:** `screencapture -V` inside the VM (60 fps), re-encoded to H.264 at 1024 px wide, 30 fps.
- **Note:** [`diagrams.md`](./diagrams.md), one fence for each of the 22 diagram types below, plus an invalid fence, an unknown type, a large flowchart and a long sequence. Small notes for single flows (`edit.md`, `large.md`, `theme.md`, `drag.md`) put a diagram at a fixed spot on screen.
- **Baseline:** master (`6ca6d21`, beautiful-mermaid) in the editor playground (`apps/playground/?full`, WebKit via Playwright), beside the same captures from this branch. Same engine as the app, same widget code; the playground pushes the app's `--ui-font` the way `theme.ts` does.

## Fixes made from QA and review

1. **Tall diagrams were clipped** (found in the playground, before the VM run). Pele lays some diagrams out much taller than beautiful-mermaid (the large flowchart is 1039×2002), and fitting stopped at the 0.25× zoom floor, so the top and bottom were cut off. Fit now goes below the floor when it has to, and zooming out stops at the fit. Verified in flow D. Test: "fits a diagram too big for the minimum zoom entirely into view".
2. **XY chart bars too loud** (comparison above). Fixed in `mermaid-canvas.css`; re-checked in the playground in both themes and in the rebuilt app ([app, light and dark](./screenshots/app/f-xy-chart-fixed-light-dark.jpg)).
3. **Review findings** (Editor and QA reviewers, commit `a78608b`): the font read forced a style recalc on every render (now read from the root's inline style); `outputLimit` lowered to 1M characters (near-limit diagrams took up to ~1 s on the main thread); errors cached; the error panel uses `role="status"` instead of an assertive alert; a private DOMPurify instance; the fit zoom floored above 0. Tests added for `updateDOM` through a live `EditorView`, fullscreen on an error, error caching and the size limit.
4. **Restyle toward master** (asked for after this QA). Accent arrowheads, muted edge labels in bordered boxes, dashed sequence lifelines, open flowchart subgraphs, lighter fills, borders and lines, 2px corners, a dotted XY chart grid, and the accent at different lightness levels for every categorical palette. Paint only: bold labels and monospace class members were left out because they would overflow the boxes Pele measured. Checked in the playground in both themes ([pie, radar, git graph](./screenshots/compare/accent-series-pie-radar-git.jpg)) and hot-reloaded into the dev app in `joel-scratch`.

## Harness problems (not app bugs)

These cost time; recorded so the next QA run doesn't chase them:

- `cliclick t:` drops the letter `e` and everything typed after it in this VM (it typed ` [Archiv]` for ` E[Archive] done`, in the plain editor as well as the diagram source panel). Type with AppleScript `keystroke` instead.
- With press-and-hold on, synthetic key events can open the accent picker, which swallows the following keys: `defaults write -g ApplePressAndHoldEnabled -bool false`, then relaunch the app.
- A scroll event posted with the ⌘ flag leaves ⌘ held for the following synthetic keys, so `0`, arrows, `=` and Esc arrived as ⌘-chords (which the canvas leaves to the app by design). Send `cliclick kd:cmd ku:cmd` after ⌘-scrolling.
- The VM shows a persistent "App Background Activity" notification over the top-right corner of the window, where the Edit code button sits; click it away before recording.
- `screencapture -V` refuses to overwrite an existing file; use a fresh name for each take.
